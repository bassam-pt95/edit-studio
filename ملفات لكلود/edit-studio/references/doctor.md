# التشخيص: كل سطر ✗ وحله

`bash "$S/doctor.sh"` يطبع تقريراً واحداً، والخروج = عدد المشكلات. الحل اللي تقدر عليه سوّه، ثم أعد التشخيص.
ما انحلّت بمحاولتين؟ اعرض التقرير كما هو وقل: «أرسل هذا التقرير لبسام، وهو يساعدك.»

| السطر | السبب | الحل |
|---|---|---|
| ✗ الجهاز غير مدعوم | مو ماك بمعالج أبل ولا ويندوز | لا حل بهالنسخة. الرسالة في الخطوة 1 |
| ✗ Node غير موجود / قديم | | غير موجود: تجهيز مهارة المونتاج `00_setup.sh --install`. قديم: تجهيز المونتاج ما يحدّثه، فبموافقته `brew upgrade node` (أو `brew install node` لو Node من مكان ثاني)؛ على ويندوز `winget upgrade -e --id OpenJS.NodeJS.LTS` ثم يسكّر تطبيق كلود ويفتحه (كلود يحفظ PATH القديم) |
| ⚠ الاستوديو مثبّت، وفحص ملفاته يحتاج Node أولاً | Node ناقص | حلّ سطر Node، ثم أعد التشخيص |
| ✗ ffmpeg غير موجود / بلا libx264 | | `00_setup.sh --install`. بلا libx264: `brew reinstall ffmpeg` بموافقته (ويندوز: `winget install -e --id Gyan.FFmpeg`، نسخة فيها libx264) |
| ✗ Python بلا أداة التفريغ | | `00_setup.sh --install` |
| ⚠ نموذج التفريغ يُنزَّل أول مرة | طبيعي | ينزل مع أول تفريغ (~3 قيقا)، قل له قبلها |
| ✗ Google Chrome غير موجود | التصدير يستخدمه (على ويندوز يكفي Edge، وهو موجود بكل ويندوز) | يثبّته بنفسه من google.com/chrome (هذا الشي الوحيد اللي يسويه بيده) |
| ⚠ معالج الجهاز ARM (ويندوز) | mediapipe وctranslate2 ما لهم نسخة ARM جاهزة | الاستوديو يعمل. الوجه أو التفريغ ما اشتغلوا؟ بايثون ARM الأصلي أفضل، وإلا كمّل بدونهم |
| ⚠ مكتبات CUDA 12 ما انلقت (ويندوز) | كرت NVIDIA بدون cuBLAS وcuDNN، والتفريغ يتوقف برسالة `cublas64_12.dll` | ثبّت CUDA 12 من موقع NVIDIA، أو شغّل التفريغ على المعالج |
| ⚠ مكتبة PyAV نسختها 15 فأعلى (ويندوز) | تكسر faster-whisper | `python -m pip install "av<15" --only-binary=:all:` بموافقته |
| ⚠ مسار بايثون أو مجلد البيانات فيه حروف غير إنجليزية (ويندوز) | mediapipe وOpenCV ما يفتحون المسار | ثبّت بايثون في مسار إنجليزي (`C:\Python312`)، واضبط `VEB_HOME` على `C:/EditStudio` |
| ⚠ الحماية من برامج الفدية (Controlled Folder Access) شغّالة (ويندوز) | تمنع node وffmpeg وpython من الكتابة في «المستندات» | يسمح لهم من أمان ويندوز، أو تنقل البيانات خارج المستندات (`VEB_HOME=C:/EditStudio`). أنت ما تغيّر إعدادات الأمان |
| ✗ تعذّرت الكتابة في … | صلاحيات أو قرص خارجي مفصول | تأكد إن المجلد موجود وتابع له. `VEB_HOME` يشير لقرص مفصول؟ يوصله |
| ✗ المساحة المتاحة قليلة | | اقترح يفرّغ مساحة؛ التحويل يحتاج ~3 قيقا والتصدير حجم المقطع مرتين |
| ✗ الاستوديو غير مثبّت | | الخطوة 4 |
| ✗ ملفات الاستوديو معدّلة | أحد عدّل ملفاته | `setup.sh --install` من الحزمة الأصلية (يرجّعها كما هي، المشاريع ما تنلمس) |
| ⚠ الحزمة نسختها X والمثبّتة Y | رفع حزمة جديدة | `setup.sh --install` |
| ⚠ تنظيف الصوت لا يعمل | أدوات الصوت (بايثون الاستوديو) ما انثبتت أو ما اكتملت | `setup.sh --install` (يحتاج إنترنت ~550 ميقا) |
| ⚠ تنظيف الصوت يعمل بالأداة القديمة | تثبيت قديم ما نزلت له الأداة الجديدة | `setup.sh --install` |
| ⚠ تنظيف الصوت: الخفيف فقط | أدوات الصوت ما اكتملت | `setup.sh --install` (يحتاج إنترنت ~550 ميقا) |
| ⚠ مشاهد الرسم لا تنتقل للاستوديو | نفس السبب | نفس الحل |
| ⚠ المنفذ 8795 مشغول | برنامج ثاني | ولا شي: الاستوديو يأخذ اللي بعده لحاله |
| ✗ ما فيه منفذ متاح بين 8795 و8814 (ويندوز) | Hyper-V أو Docker أو WSL2 يحجزون مدى منافذ | يعيد تشغيل الجهاز، وإلا `net stop winnat` ثم `net start winnat` من PowerShell كمدير (هو يشغّلهم، مو أنت) |
| ⚠ تطبيق سطح المكتب غير موجود | انحذف | `bash "$S/make-app.sh"` |
| ⚠ مهارة المونتاج ليست في ~/.claude/skills | ما تركّبت، أو انحذفت | الخطوة 0ب (تنركّب من ملف «استوديو المونتاج») |

## الاستوديو ما يفتح
1. `bash "$S/start.sh"`: يطبع «الاستوديو يعمل: …»؟ افتح العنوان بكروم.
2. «تعذّر تشغيل الاستوديو» ← آخر سطور `<البيانات>/studio/server.log` تطلع معه. ما فهمتها؟ التشخيص ثم التقرير لبسام.
3. الصفحة فاضية أو قديمة بعد تحديث ← يحدّث الصفحة (⌘R، وعلى ويندوز Ctrl+R أو F5).
4. شريط «هذه نسخة معدّلة من استوديو المونتاج» ← `setup.sh --install` من الحزمة الأصلية.
