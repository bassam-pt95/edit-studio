# التشخيص: كل سطر ✗ وحله

`bash "$S/doctor.sh"` يطبع تقريراً واحداً، والخروج = عدد المشكلات. الحل اللي تقدر عليه سوّه، ثم أعد التشخيص.
ما انحلّت بمحاولتين؟ اعرض التقرير كما هو وقل: «أرسل هذا التقرير لبسام، وهو يساعدك.»

| السطر | السبب | الحل |
|---|---|---|
| ✗ الجهاز غير مدعوم | مو ماك بمعالج أبل ولا ويندوز | لا حل بهالنسخة. الرسالة في الخطوة 1 |
| ✗ Node غير موجود / قديم | | غير موجود: تجهيز مهارة المونتاج `00_setup.sh --install`. قديم: تجهيز المونتاج ما يحدّثه، فبموافقته `brew upgrade node` (أو `brew install node` لو Node من مكان ثاني). ويندوز: `winget upgrade -e --id OpenJS.NodeJS.LTS`، وبعده يسكر تطبيق كلود ويفتحه |
| ⚠ الاستوديو مثبّت، وفحص ملفاته يحتاج Node أولاً | Node ناقص | حلّ سطر Node، ثم أعد التشخيص |
| ✗ ffmpeg غير موجود / بلا libx264 | | `00_setup.sh --install`. بلا libx264: `brew reinstall ffmpeg` بموافقته. ويندوز: `winget install -e --id Gyan.FFmpeg` (فيه libx264) |
| ⚠ تعريف NVIDIA X قديم (ويندوز) | تعريف كرت الشاشة اقدم من 580 | بموافقته يحدثه من تطبيق NVIDIA App او nvidia.com/drivers، ثم يعيد التشخيص |
| ⚠ ffmpeg ما يرمز بكرت الشاشة (NVENC) (ويندوز) | معلومة بس: الاستوديو يرمز التصدير على المعالج | ولا شي. معه سطر التعريف القديم؟ حله اول |
| ✗ Python بلا أداة التفريغ | | `00_setup.sh --install` |
| ⚠ cuBLAS موجود بس ما اشتغل على الكرت (ويندوز) | التعريف اقدم من مكتبات CUDA، او ملفات cuBLAS ناقصة | حدث تعريف NVIDIA، او `00_setup.sh --install` من مهارة المونتاج، ثم `doctor.sh --deep` (تحت) |
| ⚠ نموذج التفريغ يُنزَّل أول مرة | طبيعي | ينزل مع أول تفريغ (~3 قيقا)، قل له قبلها |
| ✗ Google Chrome غير موجود (ويندوز: ✗ ما فيه Chrome ولا Edge) | التصدير يستخدمه | يثبّته بنفسه من google.com/chrome (هذا الشي الوحيد اللي يسويه بيده). ويندوز: بموافقته `winget install -e --id Google.Chrome`، او Edge يكفي |
| ⚠ ويندوز على معالج ARM (او «معالج الجهاز ARM») | mediapipe وctranslate2 ما لهم نسخة ARM جاهزة | الاستوديو يعمل. الوجه أو التفريغ ما اشتغلوا؟ بموافقته Python 3.12 نسخة x64 (تشتغل بالمحاكاة وابطا)، وبعدها `00_setup.sh --install` من مهارة المونتاج، وإلا كمّل بدونهم |
| ⚠ الحماية من برامج الفدية (Controlled Folder Access) شغّالة (ويندوز) | تمنع node وffmpeg وpython من الكتابة في «المستندات» | يسمح لهم من أمان ويندوز، أو تنقل البيانات خارج المستندات (`VEB_HOME=C:/EditStudio`). أنت ما تغيّر إعدادات الأمان |
| ✗ تعذّرت الكتابة في … | صلاحيات أو قرص خارجي مفصول | تأكد إن المجلد موجود وتابع له. `VEB_HOME` يشير لقرص مفصول؟ يوصله |
| ✗ ffmpeg ما يقدر يكتب في مجلد البيانات (ويندوز) | «الحماية من برامج الفدية» (Controlled folder access) او برنامج حماية ثاني يمنع ffmpeg، وbash يكتب عادي | المجلد جديد ما فيه مشاريع: `VEB_HOME` برا Documents (مثل `C:/VideoEdit`) بـ`setx` بموافقته، وبعدها يسكر تطبيق كلود ويفتحه. فيه مشاريع: لا تنقله بنفسك، هو يسمح لـffmpeg.exe من Windows Security > Ransomware protection > Allow an app (المسار: `cygpath -w "$(command -v ffmpeg)"`) |
| ⚠ الحماية من برامج الفدية … شغالة ومجلد البيانات في مجلد محمي (ويندوز) | تحمي Documents وسطح المكتب والصور والفيديو والموسيقى من البرامج اللي مو موثوقة | نفس الحل، والسماح لـnode.exe ولبايثون بعد (بايثون الـvenv يشغل بايثون الجهاز: مساره من `python3 -c "import sys;print(sys._base_executable)"`). السماح لبايثون يخلي اي سكربت يكتب في المجلدات المحمية، فالنقل اسلم |
| ⚠ Smart App Control شغال (ويندوز) | ممكن يمنع ffmpeg او مكتبات التفريغ وكاشف الوجه | ولا شي لو كل شي يشتغل. انمنع شي؟ ما له استثناء لبرنامج واحد: الحل اطفاوه (Windows Security > App & browser control)، وهذا قراره هو |
| ⚠ مجلد البيانات داخل OneDrive (ويندوز) | OneDrive يزامن الفيديوهات والادوات (غيغابايتات) | `VEB_HOME` برا OneDrive (مثل `C:/VideoEdit`)، بنفس خطوات صف «ffmpeg ما يقدر يكتب» |
| ✗ المساحة المتاحة قليلة | | اقترح يفرّغ مساحة؛ التحويل يحتاج ~3 قيقا والتصدير حجم المقطع مرتين |
| ✗ الاستوديو غير مثبّت | | الخطوة 4 |
| ✗ ملفات الاستوديو معدّلة | أحد عدّل ملفاته | `setup.sh --install` من الحزمة الأصلية (يرجّعها كما هي، المشاريع ما تنلمس) |
| ⚠ الحزمة نسختها X والمثبّتة Y | رفع حزمة جديدة | `setup.sh --install` |
| ⚠ تنظيف الصوت لا يعمل | أدوات الصوت (بايثون الاستوديو) ما انثبتت أو ما اكتملت | `setup.sh --install` (يحتاج إنترنت ~550 ميقا) |
| ⚠ تنظيف الصوت يعمل بالأداة القديمة | تثبيت قديم ما نزلت له الأداة الجديدة | `setup.sh --install` |
| ⚠ تنظيف الصوت: الخفيف فقط | أدوات الصوت ما اكتملت | `setup.sh --install` (يحتاج إنترنت ~550 ميقا) |
| ⚠ مشاهد الرسم لا تنتقل للاستوديو | نفس السبب | نفس الحل |
| ⚠ مصنف الاصوات ناقص (ويندوز) | نموذج YAMNet ما نزل (التنزيل فشل او انحذف)، او بايثون الاستوديو ناقص | `setup.sh --install` (~15 ميقا من الانترنت). بدونه الاستوديو يشتغل، بس التشريح وفحص القصات بلا اسماء موثرات ولا موسيقى |
| ⚠ المنفذ 8795 مشغول | برنامج ثاني | ولا شي: الاستوديو يأخذ اللي بعده لحاله |
| ⚠ المنفذ X محجوز من ويندوز (ويندوز) | Hyper-V او WSL او Docker حاجزين مدى منافذ (`netsh int ipv4 show excludedportrange protocol=tcp` يعرضه) | ولا شي: الاستوديو ياخذ منفذ ثاني لحاله، والادوات تلقاه. لو المنافذ الـ20 كلها محجوزة ياخذ اي منفذ فاضي، وشكل الواجهة المحفوظ بالمتصفح (اللغة ومقاسات اللوحات) يبدا من الافتراضي |
| ⚠ تطبيق سطح المكتب غير موجود | انحذف | `bash "$S/make-app.sh"` |
| ⚠ مهارة المونتاج ليست في ~/.claude/skills | ما تركّبت، أو انحذفت | الخطوة 0ب (تنركّب من ملف «B Studio») |

## التفريغ على كرت الشاشة: `doctor.sh --deep` (ويندوز)
`bash "$S/doctor.sh" --deep` = التشخيص ومعه تفريغ تجريبي: نموذج التفريغ ينحمل على الكرت ويفرغ ثانية سكوت (5-10 ث، ~4.5 قيقا من ذاكرة الكرت). مو الافتراضي لانه ثقيل.
شغله لما سطور الكرت ✓ والتفريغ بطيء او يرجع للمعالج. لا تشغله وتفريغ ثاني شغال: شغل واحد على الكرت بالمرة. على الماك ما يزيد شي.

| السطر | السبب | الحل |
|---|---|---|
| ✓ تفريغ تجريبي على كرت الشاشة: N ث | التفريغ يشتغل على الكرت | ولا شي |
| ⚠ التفريغ التجريبي على كرت الشاشة ما اشتغل: … | اخر سطر من الخطا: cuBLAS او cuDNN ناقص، او التعريف قديم | `00_setup.sh --install`، وتعريف NVIDIA جديد. ما انحل؟ التقرير لبسام |
| ⚠ التفريغ التجريبي … ما خلص خلال دقيقتين | الكرت مشغول او معلق | يسكر البرامج الثقيلة على الكرت (العاب، تفريغ ثاني) ويعيد |
| – التفريغ التجريبي ما اشتغل: نموذج التفريغ مو منزل | الفحص ما ينزل شي | اول تفريغ ينزله (~3 قيقا)، وبعده يعيد الفحص |
| – التفريغ التجريبي ما اشتغل: ما فيه كرت NVIDIA | شوف سطر التفريغ فوقه | |

## الاستوديو ما يفتح
1. `bash "$S/start.sh"`: يطبع «الاستوديو يعمل: …»؟ افتح العنوان بكروم (ويندوز: او Edge).
2. «تعذّر تشغيل الاستوديو» ← آخر سطور `<البيانات>/studio/server.log` تطلع معه. ما فهمتها؟ التشخيص ثم التقرير لبسام.
3. الصفحة فاضية أو قديمة بعد تحديث ← يحدّث الصفحة (⌘R، ويندوز: Ctrl+R او F5).
4. شريط «هذه نسخة معدّلة من B Studio» ← `setup.sh --install` من الحزمة الأصلية.
